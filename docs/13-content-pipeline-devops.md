# 13. Пайплайн контента и DevOps

> **Статус:** Draft v0.1 · **Владелец:** Producer · **Зависит от:** [01. Канон](01-canon.md), [02. Тулчейн](02-toolchain.md), [03. Архитектура](03-architecture.md) · **Обновлено:** 2026-10-26

## 1. Назначение и границы

Документ описывает, как код и контент попадают из рабочей папки в билд игрока: структуру репозитория, ветки, Git LFS, CI, тесты, конвейеры контента и локализации, релизы, операции Early Access и восстановление после сбоев. Устройство кода — в [03](03-architecture.md), модели мира — в [04](04-simulation-physics.md).

Принцип: **всё, что проверяется машиной, проверяется до ревью человеком.** Код, данные, арт и локализация проходят одни ворота — зелёный PR.

## 2. Структура репозитория

Монорепозиторий, потому что версии данных и кода обязаны совпадать.

```text
engram/
├─ docs/            # Markdown-as-code, adr/, INDEX.md
├─ src/
│  ├─ Engram.Sim/        # net8.0 + netstandard2.1, БЕЗ UnityEngine
│  ├─ Engram.Sim.Tools/  # генераторы, валидаторы, headless-харнесс
│  ├─ Engram.Unity/      # Presentation: Bridge, Render, UI, Audio
│  └─ Engram.ModSdk/     # публичные контракты моддинга
├─ content/         # данные: resources, technologies, planets, factions,
│                   # civs, missions, pois, economy, ships, modules
│  ├─ localization/ # String Tables (CSV)
│  └─ schemas/      # JSON Schema 2020-12
├─ art/             # LFS: Blender/Houdini/Substance исходники, текстуры, звук
├─ unity/           # проект Unity: Assets/{Engram,Art,Scenes}, Packages
├─ tools/  ci/  tests/
```

Правила: `content/` — геймдизайнер, `art/` — художник, `src/` — программист; смешение в одном PR требует двух ревьюеров. `art/` и `content/localization/` — в LFS; `content/**/*.json` — обычный текст, диффы обязаны быть читаемыми.

## 3. Ветвление и релизные ветки

Упрощённый git-flow под непрерывную интеграцию (ADR-012).

| Ветка | Назначение | Жизнь | Защита |
|---|---|---|---|
| `main` | всегда зелёная и играбельная | постоянно | 1 ревью, все проверки, пуш запрещён |
| `feature/<issue>-<слаг>` | задача | ≤ 2 недели | PR squash-merge |
| `content/<тема>` | контентный набор (регион, акт) | 2–6 недель | контент-ревью |
| `release/<x.y>` | стабилизация, только фиксы | от M45 | cherry-pick из `main`, 2 ревью |
| `hotfix/<версия>` | срочный патч | ≤ 48 ч | от `release/*`, обратный merge обязателен |
| `sdk/<версия>` | снимок моддинг-SDK | по релизам | тег |

Правила: PR в `main` ≤ 400 строк кода (исключение — миграции и генераторы); контентные PR меряются ассетами. Версии `MAJOR.MINOR.PATCH`: MAJOR меняет формат сейва (см. [03](03-architecture.md), §8), MINOR — контент и механики, PATCH — фиксы. **Каждый тег собирается из `release/*`**, иначе билд невоспроизводим.

## 4. Git LFS-правила

LFS включается по расширению, а не «по размеру»: иначе поведение непредсказуемо.

| Категория | Расширения | Locking |
|---|---|---|
| DCC-исходники | `.blend`, `.spp`, `.hiplc`, `.hda`, `.psd`, `.kra` | да (`.blend`, `.psd`, `.hda`) |
| Модели | `.fbx`, `.glb`, `.abc` | нет |
| Текстуры | `.exr`, `.tif`, `.png` ≥ 2048 px, `.tx` | нет |
| Аудио/видео | `.wav`, `.flac`, `.ogg`, `.mp4` | нет |
| Симуляции | `.vdb`, `.bgeo` | нет |
| Данные Unity | `.asset`, `.unity`, `.prefab` — **не LFS** | нет |

Ограничения: файл ≤ 2 ГБ, суммарный LFS ≤ 300 ГБ к 1.0; > 500 МБ — исключение через ADR. Запрещено коммитить `Library/`, `Temp/`, `Build/`, `obj/`, `Logs/` и сторонние ассеты с неясной лицензией. Переход на Perforce Helix Core (канон, раздел 4) — при > 12 активных пользователях VCS, клоне дольше 20 минут или частых конфликтах lock-ов; решение — ADR, миграция — отдельный спринт.

## 5. CI: стадии и матрица

GitHub Actions + GameCI на self-hosted-раннерах (2 Windows, 2 Linux). Бюджеты: PR ≤ 45 минут, ночная сборка ≤ 3 часа.

| # | Стадия | Что делает | Блокирует merge | Время |
|---|---|---|---|---|
| 1 | `lint` | `dotnet format`, анализаторы (запрет `UnityEngine` в симе, запрет `float`), линт YAML/JSON | да | 3 мин |
| 2 | `schema` | валидация `content/**` по JSON Schema, ID и ссылки | да | 2 мин |
| 3 | `sim-unit` | `dotnet test` без редактора, покрытие ≥ 80% | да | 6 мин |
| 4 | `sim-golden` | короткий golden-hash (1 день, 1 год) | да | 10 мин |
| 5 | `unity-editmode` | Unity Test Framework, EditMode | да | 12 мин |
| 6 | `unity-playmode` | PlayMode, сцена вертикального среза | да | 25 мин |
| 7 | `build-win` | IL2CPP Windows x64 | да | 40 мин |
| 8 | `build-linux` | IL2CPP Linux x64 (Proton/Deck) | да | 35 мин |
| 9 | `content-audit` | нейминг, битые ссылки, размеры LFS, дубли | да | 8 мин |
| 10 | `loc-sync` | покрытие RU/EN, битые ключи | да | 5 мин |
| 11 | `steam-upload` | закрытая ветка Steam | только на тег | 20 мин |
| 12 | `nightly` | полный golden-hash (36 эталонов), перф-бенчмарки, загрузка 3 сейвов прошлого релиза, сборки, отчёт | — | 3 ч |

Матрица: Windows Server 2022 (`win-x64`) и Ubuntu 24.04 (`linux-x64`); Unity пинится из `ProjectVersion.txt`, образ GameCI — по тегу. Кэш: LFS-медиа, `Library/` по хэшу `Packages/`, NuGet. Артефакты — 90 дней, релизные — бессрочно. Активация Unity — через License Server/ULF-секреты; провал активации — алерт, а не молчаливый красный PR. Ночная сборка, упавшая две ночи подряд, — блокер дня.

## 6. Пирамида тестов

| Уровень | Инструмент | Что тестируется | Объём к 1.0 | Время |
|---|---|---|---|---|
| Модульные | xUnit/NUnit | формулы, экономика, RNG, интегратор | ≈ 4 000 | < 3 мин |
| Свойства | FsCheck | инварианты: масса/импульс, `Δp/p`, монотонность | ≈ 120 × 100 генераций | < 5 мин |
| Интеграционные | харнесс Sim | 1 день / 1 год / 10 лет экономики | ≈ 40 сценариев | < 20 мин |
| Golden-hash | свой runner | детерминизм 12 сценариев × 3 длины | 36 эталонов | ночь |
| Системные | Unity PlayMode | загрузка, сейв/лоад, стриминг, переходы | ≈ 60 | < 25 мин |
| Приёмочные | чек-листы | вертикальный срез, ощущения | 1 на веху | вручную |
| Производительность | профайлер | 60 FPS @1440p, L0 ≤ 20 мс, Deck 40 FPS | 8 бенчмарков | ночь |

Правило: каждый воспроизводимый баг из публичного трекера получает автотест. Числа канона (2 500 узлов, 64 цивилизации, 36 ресурсов, 320 техузлов) проверяются генератором-инвариантом — расхождение валит сборку.

## 7. Конвейер контента

| Стадия | Инструмент | Выход | Проверяет |
|---|---|---|---|
| Блокинг | Blender | серые меши, масштаб в метрах | Tech Artist |
| Процедурная основа | Houdini (HDA) | FBX/EXR/VDB-бейки | Tech Artist |
| Детализация | Blender + Substance | FBX + 4K PBR | Environment Artist |
| Экспорт | аддон `eng_export` | FBX с проперти + JSON | автомат |
| Импорт | пресеты `AssetPostprocessor` | префаб, материалы, коллайдеры | автомат |
| Сборка сцены | редактор `System Builder` | сцена + данные | Level Designer |
| Ревью | PR + чек-лист контента | апрув | арт-лид |

Импорт-пресеты версионируются: 1 unit = 1 м, `Read/Write` выключен для статики, компрессия `BC7`/`BC5`/`BC4` по каналу, LOD-группы, lightmap UV. Нарушение пресета — ошибка `content-audit`, а не «на усмотрение художника».

HDA: любая процедурная система (планеты 12 типов, пояса 2 000–200 000 объектов, туманности) — параметризованная HDA с версией, воспроизводимые бейки, PDG-граф в репозитории. Ручная правка бейка без обновления HDA — дефект пайплайна.

## 8. Нейминг

`sm_` статика, `sk_` скелет, `tx_` текстура, `mat_` материал, `vfx_`, `anm_`, `snd_`; данные — `snake_case` с namespace (`res.rare_earths_ytterbium`). Только латиница, нижний регистр, без пробелов и кириллицы в путях (ломает Linux-сборку и CI). Варианты — `_varNN`, размер — `_4k`, LOD — `_lodN`. ID данных стабильны: переименование ID = миграция сейва.

## 9. Пайплайн локализации

Unity Localization + Crowdin (канон, раздел 4); RU/EN на релизе, DE/FR/ES/PL/ZH после EA.

| Шаг | Правило |
|---|---|
| Строки | только ключи в String Table; в коде и данных текста нет |
| Ключи | `feat.<система>.<смысл>`, например `feat.market.price_hint` |
| Обмен | CSV-экспорт из Unity → Crowdin → обратный импорт; ручные правки в Unity запрещены |
| Плейсхолдеры | `{0}`, `{count}`, валидация совпадения в CI |
| Плюрализация | Smart Strings: RU — 3 формы, EN — 2, тест на все формы |
| Термины | глоссарий канона (раздел 16) обязателен для подрядчика |
| Длина | метаданные `max_chars` у UI-строк, линтер ловит превышение; контекст — скриншотом |
| Приёмка | LQA по RU/EN на каждой вехе, «непереведённых» в релизе — 0 |
| Шрифты | кириллица + латиница, раздельные атласы по языкам |

## 10. Валидация данных

Пять автоматических ворот: (1) **схема** — JSON Schema 2020-12, обязательные поля и диапазоны; (2) **ID-линт** — уникальность, формат, стабильность, реестр `content/.ids.json`; (3) **ссылки** — каждая разрешается, битая = ошибка, не warning; (4) **инварианты канона** — 2 500 узлов, 64 цивилизации, 210 фракций, 22 вида, 36 ресурсов, 320 техузлов, 12 типов планет, а также экономические тождества (`Δp/p = −k·Q/V`, восстановление цены 3–20 дней); (5) **балансовые прогоны** — headless 10 лет: нет гарантированных банкротств и пузырей, инфляция 1–4%/год удерживается. Исключение — только через dev-флаг в данных и запись в CHANGELOG данных.

## 11. Modding SDK и Steam Workshop

| Элемент | Решение |
|---|---|
| SDK | `sdk/<версия>`, тегируется с релизом, архив + локальная лента |
| Мод | `mod.json` (id, версия, gameVersion, зависимости, priority), `data/*.json`, опционально `scripts/*.lua` |
| API | `Engram.ModSdk`: чтение состояния, события, регистрация данных; без файловой системы и сети |
| Песочница | Lua 5.4: лимиты инструкций/памяти, запрет I/O, детерминированные часы |
| Упаковка | `.engmod` (zip) + каталог для Workshop |
| Workshop | Steam UGC + отдельный загрузчик, проверка схем при публикации |
| Модерация | только бесплатные моды, без ассетов с неясной лицензией, метка «меняет баланс» |
| Совместимость | несовместимый мод не грузится молча — отчёт конфликта |
| Документация | `docs/modding/` + пример мода; обновляется в том же PR, что API |

Правило: SDK содержит только контракты, не код игры — иначе моды сломаются при первом рефакторинге.

## 12. Docs-as-code

Markdown в `docs/`, сборка MkDocs Material, публикация на каждой вехе. CI проверяет битые относительные ссылки, орфографию (RU/EN), запрет абсолютных путей. Шапка — по шаблону канона (раздел 2). ADR в `docs/adr/NNNN-<слаг>.md`, неизменяемы после принятия; отмена — новый ADR со статусом `Supersedes`. Числа цитируются из канона ссылкой, дублирование чисел — ошибка ревью. Снапшот доков релиза — `docs/versions/<x.y>/`.

## 13. Таск-трекинг

GitHub Issues + Projects как единый трекер (ADR-013). Метки `type/*` (bug, feature, content, tech, docs, balance), `area/*` (sim, render, ui, audio, pipeline, loc), `sev/*` S1–S4, `stage/*`. Обязательны веха (`M16`, `M45`, `1.0`), оценка, ссылка на дизайн-документ. Работа без issue — только если < 2 часов; PR ссылается на issue и на тест; веха закрывается при нуле S1/S2; техдолг — не менее 15% спринта.

## 14. Релизный процесс и патчи

| Шаг | Действие | Ответственный |
|---|---|---|
| 1 | Feature freeze, `main` → `release/x.y` | Producer |
| 2 | RC1: полный прогон, golden-hash, 72-часовой тест | QA Lead |
| 3 | Ветка `rc` в Steam, внутренний плейтест, LQA, Deck | QA Lead |
| 4 | Fix-окно S1/S2, RC2…RCn с полным прогоном | команда |
| 5 | Сборка из `release/x.y`, SteamPipe depots (win/linux), символы в архив | Tools/Engine |
| 6 | `public-beta` на 2–7 дней, затем default | Producer |
| 7 | Merge в `main`, тег `vX.Y.Z`, CHANGELOG | Tools/Engine |

Патчи в EA: регулярный — каждые 3 недели, хотфикс S1 — в течение 48 часов, контентный — раз в квартал; аддоны после 1.0. MAJOR-изменение формата сейва требует миграции ([03](03-architecture.md), §8) и предупреждения в патчноуте. Заметки: RU/EN, разделы «новое / изменено / исправлено / известные проблемы».

## 15. Краш-репортинг

Sentry (self-hosted), приём только по согласию, опция «не отправлять» на первом экране. Данные: стек, версия билда, символы IL2CPP, ОС/GPU/драйвер, 60 с лога, набор модов; **без PII и без сейва**. Символы загружаются на каждом релизе, их отсутствие — красная сборка. Дедупликация по стеку и мод-набору, дежурство ротацией на неделю, S1 — алерт и блокер следующего патча. Цели: crash-free sessions ≥ 99,5% на 1.0, ≥ 98% в EA. Телеметрия — opt-in, без PII; в неё входят «симуляция не успевает», FPS-гистограммы, отказы контента.

## 16. Операции Early Access

EA — M45 (2030-08), за 6 месяцев до 1.0. Задача: удержать доверие и не сломать сейвы.

| Практика | Правило |
|---|---|
| Роадмап | публичный, обновляется после вехи, без дат без запаса |
| Обратная связь | Steam-форум + Discord + форма в игре; дежурный по сообществу — 1 в неделю |
| Патчноуты | RU/EN, всегда с разделом «что дальше» |
| Сейвы | совместимость в пределах MAJOR; перед рискованным патчем — предупреждение и бэкап |
| Прозрачность | публичные графики телеметрии (без PII) |
| Моды | SDK и Workshop доступны **до** EA |
| Метрики | 50% возвращаются после первого часа, 25% играют 20+ ч (канон, 00) |
| Кризис | хотфикс, публичный пост с причиной, постмортем внутри |

## 17. Бэкапы и восстановление

| Что | Как | Периодичность | RPO/RTO |
|---|---|---|---|
| Git-репозиторий | GitHub + push-mirror на self-hosted | каждый пуш | 1 ч / 2 ч |
| LFS-медиа | второй S3-совместимый бакет, репликация | ежедневно | 24 ч / 4 ч |
| Артефакты релизов | архив + SteamPipe | каждый релиз | 0 / 1 ч |
| Секреты CI | зашифрованный бэкап (KMS) | еженедельно | 7 дней / 4 ч |

Правило 3-2-1: три копии, два носителя, одна вне площадки. Локальные машины бэкапом не считаются. Квартальный drill: восстановление репозитория и LFS на чистой машине и сборка из восстановленного клона; провал drill → в ретро. Бэкап без проверки восстановления — не бэкап.

## 18. Открытые вопросы

1. **LFS к 1.0** — оценка 220–300 ГБ: удержит ли GitHub LFS или Perforce нужен уже к M24.
2. **Загрузчик Workshop** — свой в `tools/` или Steamworks-утилита; влияет на модерацию.
3. **Ночной golden-hash** — считать ли Deck-профиль отдельной платформой сравнения.
4. **Хотфикс 48 ч** при команде 11 человек — реально ли, или SLA делить на «S1 в игре» и «S1 в симуляции».
5. **Монорепозиторий vs отдельный арт-репозиторий** при LFS > 300 ГБ и подрядчиках.

## 19. Предложения к канону

1. Раздел 4: добавить «ночные сборки и golden-hash — ежедневный гейт; сборка из незелёного `main` запрещена» — канон фиксирует CI как инструмент, но не SLA.
2. Раздел 17: добавить «crash-free sessions ≥ 99,5% на 1.0» и «хотфикс S1 ≤ 48 ч в EA».
3. Раздел 20 (вопрос 4): предложение — чанк на регион (≈ 200 узлов) + отдельные чанки для 400 знаковых систем; перенести решение в канон после прототипа M8.
4. Раздел 4: уточнить, что Git LFS — для исходников арта, а не для Unity-сцен и префабов (текстовые форматы должны диффиться).
5. Раздел 11: зафиксировать, что SDK моддинга публикуется **до** Early Access.
